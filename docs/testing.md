# Testing from a clean checkout

Use a supported Node version from `package.json`, then run these commands at the repository root:

```sh
scripts/pnpm install --frozen-lockfile
scripts/pnpm check
```

`check` builds the current source, runs the default Vitest suite, checks TypeScript, and lints the package. `scripts/pnpm test` alone expects that build to exist. No historical tarballs, existing DSH profile, desktop installation, model credentials, or Git history are needed. Test-owned temporary files and synthetic receipts are created under `.dsh-dev/`; existing local data is preserved.

The default suite includes real Node subprocesses, local loopback fixtures, property sequences, and DOM doubles. A passing default check does not prove complete DSH CLI Host activation, desktop/browser interaction, or real-model behavior. Existing `it.fails` cases retain their explicit expected-failure semantics.

## Current packed installation and cache guards

`tests/deepening/v041-cache.spec.ts` packs the current build using `scripts/pnpm pack` into a unique `.dsh-dev/current-cache/` directory, then extracts it into independent installations. The shared `scripts/verify-package.mjs` audits packed metadata, source bytes, publication allowlist, notices, and complete Host manifest coverage. Cold Node processes also verify every Host manifest digest and concrete package export. They exercise fresh linkage, changed/missing modules, linker failures, missing/invalid/version-mismatched manifests, cached unversioned or wrong-version namespaces, and an already-cached bootstrap after disk replacement. Failed installations must show the bilingual restart message before accessing Host services. These deliberate mutations are synthetic current-install tests, not historical release reconstructions.

The tarball and installations are removed when the suite finishes. No `dist/` fixture is read or overwritten. Focused verification after building:

```sh
scripts/pnpm -F dsh-bot exec vitest run --config ../../vitest.config.ts tests/deepening/v041-cache.spec.ts tests/deepening/release-fixtures.spec.ts tests/deepening/catalog-validation.spec.ts
```

## Historical release suite

Historical cache/upgrade checks are deliberately excluded from the default configuration and retained in `tests/deepening/v041-cache.release.spec.ts`. Run them explicitly:

```sh
node packages/dsh-bot/tests/deepening/release-fixtures.mjs
scripts/pnpm test:release
```

The suite requires the original release archives at the following paths. The SHA256 values are pinned in the verifier, anchored by the original tracked acceptance receipts; local `.sha256` sidecars are not trusted.

| Required original artifact | SHA256 | Original receipt |
| --- | --- | --- |
| `dist/dsh-bot-0.3.2.tgz` | `1cad1685ae60deef5197a374d2213bb160cb5246eea4ad3e449035de050f986b` | [V032](acceptance/V032-bot-to-bot.md) |
| `dist/dsh-bot-0.4.0.tgz` | `361481e8a623a5473bb897553f9508346dcfa39014c7506ddda788d93b1498b1` | [Deepening](acceptance/deepening.md) |
| `dist/dsh-bot-0.4.1.tgz` | `3675fdb29a16f679aa5cfc1097afb839a54b1c8d8d8c78ad19d44f4f66f2f9eb` | [V041](deepening/V041.md) |

Obtain these exact archived bytes from the release maintainer or a published release carrying the same checksum. The repository does not ship or automatically download those archives, and does not claim an unverified download URL exists. Do not build current source under an old version number or rename a current tarball. Missing or modified archives produce a nonzero exit with every failed path and expected checksum. There is no skip-on-missing mode. The verifier CLI optionally accepts an alternate directory for read-only preflight; the release suite itself always uses `dist/`.

The six retained cases are fresh 0.4.1, genuine 0.3.2 schema cache → 0.4.0 `memoryFields` link failure → 0.4.1 safe rejection, mixed install, linker error, cached 0.4.0 module, and cached entry after disk replacement. This proves native Node ESM boundaries with real packages. Complete CLI Host hot upgrade/cold recovery remains a separate explicitly invoked workflow documented in [V041](deepening/V041.md); this suite never claims that evidence.

## Default-suite local-input audit

| Input family | Reproducibility |
| --- | --- |
| `packages/dsh-bot/lib/` and package self-exports | Generated by `check`'s build step; bundle tests and the current packed-install test validate actual outputs. |
| `node_modules/` and public DSH packages | Supplied by the frozen lockfile installation. No global packages or reference checkout are used by the default tests. |
| `evals/`, `docs/implementation/v061-permission-locales.json`, tests' JSON/YAML/snapshots | Tracked inputs, including retrieval freeze hashes and expected counterexamples. |
| `scripts/deepening/`, `evals/scorers/`, `spikes/p34/src/`, package screenshot helpers | Tracked tooling transitively imported by default tests; local synthetic processes use these sources. Manual profile/release/performance scripts that read older receipts are not discovered as default tests. |
| `.dsh-dev/` | Created before use by test fixtures. No old Host receipts/profile are required; the platform launcher `--check` reports an absent profile without failing. |
| `.codex/runs/PROGRESS.md` | Optional live catalog delta input only. Its absence is supported. The historical catalog uses the already tracked `evals/inputs/failures-progress.md`, never requires a local progress log. |
| Baseline Git objects | Replaced at runtime with `evals/inputs/failure-sources.json`: 49 original tracked blobs from commit `66db1ea03b52237ba499a3c2642a4caf4c6d12f9`, 649,229 bytes. Existing `failures.json` and `manifests/failures.json` verify their original SHA256 values. |
| Historical `dist/*.tgz` | Used only by the explicit release suite above. No default test depends on these ignored archives. |

The catalog regression creates a source-only fixture tree without `.git` or `.codex/runs` and validates it in a child process whose `PATH` cannot resolve Git. The snapshot contains only the original tracked `docs/`, `tasks/`, and one package source blob; it adds no ignored progress/log content. If the historical baseline is intentionally changed, maintainers with the original Git objects can regenerate this snapshot using `node scripts/deepening/freeze-source-blobs.mjs` after removing only the obsolete snapshot under review. The command validates all original digests and refuses to overwrite any existing snapshot. Routine checks neither regenerate nor update frozen evidence.
