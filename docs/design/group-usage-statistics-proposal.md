# 群聊执行统计与用量展示方案（已批准）

日期：2026-11-01（America/Los_Angeles）。初稿为设计；用户后续已批准实施，见 `tasks/S0-S2-group-statistics.md`。初稿未实施产品功能、修改正式安装或发起真实模型请求。

实施更新（2026-11-02）：S0 证实 dock 独占声明无法独立复用；按第 6 节已批准的 fallback 使用公开 projection。实现与运行边界见 [S0–S2 验收记录](../verification/group-statistics/README.md)。

## 1. 建议批准的范围

补齐群聊底部统计，同时让每个问题下的每位 Bot 都能查看自己的原生统计。采用“问题 → 成员 → 原生子会话”的统计归属。

1. 每个问题下：在既有可折叠执行区域中增加成员统计，优先复用官方轮次、步骤、速度、Token 和缓存控件。
2. 输入框下：增加一行可切换问题的汇总；不放历史执行卡、不自动展开面板，避免再次挤压聊天区。
3. 汇总仅覆盖选定问题的直接成员会话，显示宿主已记录的用量；速度、上下文占用保留成员视角。
4. 先通过 rc.2 / rc.5 原生 API 验证，再实现与验收；不修改调度、模型选择、审批、停止或多轮协作语义。

首版不做：全群历史总账、金额换算、按每条消息/每次 delivery 分摊消耗、后代子代理/独立后台任务成本归集、群总速度或单一群上下文百分比。
“没有任务”仍按现有机制自然空闲；统计不会新增轮次、自动续聊或后台模型请求。

## 2. 当前事实与原生复用边界

| 能力 | 当前核实结果 | 设计选择 |
| --- | --- | --- |
| 群输入区 | 插件接管 `conversation.composer`，没有渲染原生统计 dock | 在现有输入区下增加小型汇总，不替换整个群输入实现 |
| 群根会话 | 禁止直接模型请求，不能代表各成员消耗 | 不读取 root 的空统计冒充群用量 |
| 成员原生统计 | 公开 `conversation.composer.dock`，原生条目为 `activity`、`usage` | 通过子会话 `SessionProvider` 和 slot 组合复用，不内部导入组件 |
| 选择统计条目 | slot 的公开 `RenderOpts.only` 可选择条目；父 entry 需声明 children | 验证只呈现统计、无发送入口、无其他不相关 dock 项 |
| 统计数据 | 公开会话 projection：`sessionStats`、`tokenUsage` | 汇总只读公开 projection，完整 baseline 未到时不冒充完整统计 |
| 上下文圆环 | rc.2 的 `ContextMeter` 位于默认 Composer 内，未独立导出/注册到 dock | 先验证公开组合；无法复用时，以公开 `contextPressure` 做只读文字/小指示器 |
| 子会话生命周期 | 既有成员过程使用 `sessions.retain(SubagentAddress)` 与 release | 复用明确的父子地址、异步就绪检查及 effect 生命周期 |

以上是 **rc.2 发布包的声明和实现核查**，不是新统计 UI 的运行验收。指定的参考源码目录在当前机器不存在，未修改替代源码。
rc.5 曾通过现有群过程验收，但本轮尚未独立验证其统计接口；不能用旧过程面板通过替代本次 API spike。

原生组件与数据的范围也有限制：原生 activity/usage 是整个成员会话累计，不是一次 delivery 的用量；activity 在完整统计缺失时可能退回已加载窗口。汇总不能直接采用这个窗口回退值并宣称全量。

只有两处预计需要插件自身展示：跨成员的合计行，以及可能无法直接复用的上下文占用小控件。理由分别是官方统计以单会话为单位、上下文 UI 没有独立公开入口。都不重做原生 Token 计量或维护新的账本。

## 3. 页面与交互

### 3.1 每个问题下的执行区域

继续复用现有 `GroupTurnExecution`，默认折叠，不新增常驻大面板。展开后每个成员依次显示身份/状态、统计、可折叠思考过程；已有查看详情、补充、停止入口保持位置和语义。

示意数字为设计样例，非实测结果：

```text
                                      你：请一起比较两个方案

▾ 执行详情 · 3 位成员 · 执行中
    研究助手  执行中                       查看详情  ···
    模型 2 轮 3 步 · 218 tok/s | 11.8k tok · 缓存 40% | 上下文约 18%
    ▸ 思考过程 ……

    审阅助手  等待输入
    模型 1 轮 2 步 · 126 tok/s | 7.2k tok · 缓存 20% | 上下文约 12%
    ▸ 思考过程 ……
```

- 原生统计的图标、格式和统计详情交互优先保持官方实现。速度 tooltip 解释为“平均解码速率”，不是瞬时吞吐量。
- 上下文标为“约”，来源是该成员最近可用的原生估计；已结束成员注明“最后一次估计”。
- 同一成员同问题多轮共用 child 时只显示一次累计，不在每条 Bot 回复下复制相同统计。
- 旧串行记录可能一名成员对应多个 child：成员行显示可加总指标，详情按执行列出原生统计，不拿最后一次 child 冒充全部；不同 child 的速度/上下文分别显示。
- 未被底栏选中且未展开的历史问题不新建订阅。已经取到的汇总可用于折叠摘要；未取过时保留现有摘要，不显示虚假的 0。

### 3.2 群输入框下方的一行汇总

详细模式桌面示例：

```text
[ 输入框与现有模型、权限、发送控件                          ]
本次问题 ▾ · 2 位执行中 · 模型 6 轮 8 步 · 23.6k tok · 缓存 40% · 详情
```

这里的数字均为“所选问题的直接成员会话已记录统计”。“模型轮/步”与“群协作轮次/自动后续额度”不同，后者仍在原来的执行限制说明中，不混为一个计数。

- 默认跟随最近由用户发起的问题；有正在运行的问题时，首次打开群优先选最近的活动问题，否则选最近问题。
- 用户手动切到历史问题后固定该选择，流式消息、Bot 间请求和滚动不会自动切回；点击“跟随最新”或成功发送新的独立问题才恢复跟随。
- 对旧问题的“补充”归原问题，发送成功后底栏定位该问题。新消息引用旧答案仍是新问题。
- 多个问题并行时显示“另 N 个问题执行中”，点击同一个问题选择菜单查看；不把各问题的用量偷偷混合。
- 暂停后显示“已暂停”，取消后显示“已停止”，空闲后保留最后已记录统计；不把“空闲”写成“业务目标已完成”。
- 新群尚无问题时不显示数字；提交后先显示等待/加载状态，收到原生记录再更新。

点击“详情”使用公开的原生弹层控件，展示成员名称、模型、状态、输入/输出/缓存分项和数据范围说明。窄屏用原生适配的对话框；Escape、点外部关闭、焦点返回触发器，均按官方交互。查看详情不打开可编辑子会话。

### 3.3 显示偏好、窄屏与缺失数据

- 优先继承宿主“性能与用量”的详细/简洁偏好，不另造一套全局设置。公开候选是 `configForms.get('ui-chat')` 的 snapshot/subscribe，跟随宿主已接受的 `performanceUsage`，不依赖内部乐观状态、也不承诺同一时刻切换；组合在 S0 验证。不可用时提供固定紧凑汇总并说明，不读内部 store/localStorage。原生成员条目仍按宿主自身偏好呈现。
- 详细模式窄屏默认只显示“本次问题 · 已记录 Token · 执行状态 · 详情”，模型轮/步和缓存放到详情。简洁模式以状态、可用缓存指标及详情入口为主，不强制展示被宿主偏好隐藏的统计项。
- 桌面默认一行；窄屏最多两行自然换行。不新增执行卡列表，不固定高度占据消息区，不通过跑马灯或横向滚动容纳数据。
- 已加载成员为 2/3 时显示“部分统计 · 2/3 位可读取”；这个覆盖数不是提供方用量完整率。旧串行成员可能有多个 child，只有全部预期 child 就绪才算该成员可完整读取；仅部分 child 可读时标注成员数据不完整。
- 成员未启动显示“等待执行”；baseline 未到显示“加载统计”；没有提供用量显示“尚无用量报告”；历史不可读显示“记录不可用”。缺失不填 0，不显示假的 0% 缓存命中。
- 历史回读时先显示读取状态，不把上一个 Bot/问题的数字带入新选择。动效、文字颜色、间距使用原生组件与主题 token；数字更新不抢焦点、不强制滚动。
- 语言覆盖中文/英文，亮色/暗色，1440 / 768 / 390 px；辅助技术不逐 token 播报，仅播报状态变化。

## 4. 指标口径

| 指标 | 定义和显示范围 | 群汇总规则 |
| --- | --- | --- |
| 模型轮次 | 原生定义：至少有一个结束步骤的模型 turn；拒绝或空 turn 不计 | 唯一直接 child 的原生轮次相加，不等于用户问题数 |
| 模型步骤 | 原生结束的 `step/end`，包含成功、失败、取消；未结束步骤不提前计入 | 相加；当前是否执行中来自群状态另行显示；不把 delivery 数当步骤数 |
| Token | 未缓存输入 + 缓存读 + 缓存写 + 输出；四个桶互斥，reasoning 已计入输出 | 按唯一 child 加总已记录桶，不重复加 reasoning；不代表金额或语义文本长度 |
| 缓存命中率 | 缓存读 /（未缓存输入 + 缓存读 + 缓存写） | 先合计分子分母再相除；不平均成员百分比；输入分母为零时显示“—” |
| 速度 | 原生纳入有效时间记录的 decodeTokens / (decodeMs / 1000)，单位 tok/s；仅相关已结束记录 | 仅成员展示，不相加/平均为一个“群 tok/s” |
| 上下文占用 | 原生 `projectedTokens ?? pressureTokens` 与 `contextWindow` 形成的近似值 | 仅成员展示，无统一群窗口；不能把 Token 累计数当上下文占用 |
| LLM/工具耗时、TTFT | 按原生成员详情定义 | 首版不新增群总耗时，避免把并行时长相加当墙钟时间 |

缓存例子：A 的输入 100、命中 80；B 的输入 900、命中 90。汇总应是 `(80+90)/(100+900)=17%`，不是 `(80%+10%)/2=45%`。

统计只表明宿主已记录的信息。projection 就绪不证明每个模型请求都报告了完整用量；若没有公开的请求覆盖信息，不能标“精确总消耗/全部费用”。未知或未报告部分始终不估算为字符数或成本。
失败、取消、skip、没有最终正文也可能消耗 Token，保留已知量；执行状态未知和数值可读取是两个独立维度。

上下文估计不用于计费、停止或调度。原生分子/容量可能分别更新，切模型时存在短暂不一致；新实现不能强化为精确值。可识别不一致时显示“更新中”，不能识别时保留“估算”说明。不同成员使用不同模型上限也分别显示。

首版明确不包含成员另行启动的后代子代理或独立后台任务；不要把这里的数字标为整项工作的完整账单。S0 必须核实原生 projection 是否隐含后代归集，若有则先排除重复计数并准确标注范围；不能只凭字段名称判断。

## 5. 数据归属与实现设计

### 5.1 去重和历史边界

身份：`groupId + groupCreatedAt + turnId + memberId`。计量读取身份：`rootSessionId + childSessionId`。

- protocol 2 仅在同一问题、同一成员内续用 child；A→B→A、忙碌 inbox 和人工补充会增加同一 child 的原生统计，不再复制整份累计。
- `message-published` 回执会复制 delivery 字段；`joinedDeliveryId` 也不代表新 worker。通过真正执行记录构建唯一 child 集合，归并关联回执；不能依赖回执行数、outputMessageId 或最后一条 delivery。
- 旧串行模式一名成员可有多个 child，全部唯一会话纳入该问题；如发现同一 child 跨问题/成员归属冲突，标异常、暂停该部分汇总，不复制进两个桶。
- 普通引用旧回答只新增新请求的输入消耗，不重新计入旧请求历史。消息翻页不改变选定问题的计量集合。
- 读取完整持久 projection；缺少时只展示可核实部分。原生 activity 的已加载窗口 fallback 不作为完整群合计。
- 重启后 unknown 记录不重放。只读回放原生已存统计；不以重启时间冒充执行终点，不通过补跑模型“补齐统计”。

### 5.2 拟增组件与数据层

| 单元 | 责任 |
| --- | --- |
| `GroupStatsSource` | 筛选问题/成员，唯一 child 去重、共享只读引用、订阅及释放、统计状态与纯聚合 |
| `GroupMemberStatistics` | 在准确的子会话 provider 下渲染原生 activity/usage，及必要的上下文薄展示层 |
| `GroupStatisticsBar` | 群输入框底部，所选问题的紧凑汇总与范围切换 |
| `GroupStatisticsDetails` | 按需打开成员明细，原生弹层与键盘交互 |

名称为拟议内部实现，不新增产品术语。现有 `GroupTurnExecution`、`GroupMemberProcess` 与 `WorkspaceGroupComposer` 接入该数据层，身份选择器共用，避免各写一套去重。
不新增 Token 数据库、Host 计费服务或统计 Remote。只有 S0 证明既有公开数据确实不能满足后，才另提补充设计，不以读取内部 store 代替。

若类型引用需要 `dsh-session-stats/client`、`dsh-token-meter/client`，按项目规则增加精确 rc.2 开发依赖；不因类型引用新增 runtime peer、不升级宿主。

### 5.3 性能、生命周期与只读性

- 默认只订阅选定问题、显式展开的成员过程/统计。不同组件引用同一 child 时共用数据源与引用计数。
- 不为未被底栏选中且未展开的历史卡、未打开的群或全量群历史创建 session 引用；关闭群/组件、切换范围、插件卸载都释放。
- `pending/starting` 的保留 ID 不代表原生会话已创建，沿用父子地址和 readiness 检查。异步回调带身份/代次校验，防止迟到结果污染新群或新 Bot。
- 以 projection 事件订阅更新，不轮询重扫完整日志；同一渲染帧合并更新。必要的并发加载上限纳入配置和校验，S0 根据实测给出默认值。
- 历史统计按需读取；折叠后可保留只读数字快照，但必须在再次打开时验证身份和当前状态，不维持后台模型运行。
- 统计动作不得调用 prompt、followup、startActivation 或恢复执行；禁止挂载完整默认 composer 再用 CSS 隐藏输入，也禁止导入 DSH 内部组件。

## 6. 分阶段实施与验收门禁

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| S0：原生 API spike | rc.2 / rc.5 隔离 Host 证据、公开入口记录、统计范围核对 | child provider 下的 dock 可达；activity/usage 可单独渲染；与同一 child 原生单聊统计一致；只读与释放通过；上下文/偏好/完整日志能力分别确认 |
| S1：逐成员统计 | 问题下原生统计、状态与上下文展示 | 多轮去重、旧串行多 child、取消/失败用量保留、缺失明确；中英/亮暗/窄屏通过 |
| S2：底栏与收尾 | 问题选择、合计与明细、兼容降级、验收报告 | 聚合正确、多问题不串数、范围明显、生命周期无泄漏、完整检查及打包通过 |

本方案已批准，现由 Issue #23 / Draft PR #24 跟踪 S0 → S1 → S2。S0 使用隔离脚本化模型，不访问正式数据，也不验证真实模型推理质量。
若原生统计控件不能通过公开组合使用，不直接复制内部实现：保留公开 projection 的简要只读数值方案和原因；涉及新增 Host/Remote/数据迁移或无法保证只读的方案调整，重新提交审批。

至少包含以下验收：

1. A→B→A、忙碌 inbox、普通进度与人工补充：每个请求只计一次，重复 delivery 不放大统计。
2. 两个问题同时调用同一个 Bot；新问题引用旧问题：归属独立，手动选择不被流式事件抢走。
3. 取消、失败、skip、无最终正文、模型不报 usage、缺少 projection：已知量保留，未知不变成 0。
4. 100/80 与 900/90 的缓存样例得 17%；reasoning 不重复加；不同模型的上下文不求和。
5. 三个数据不完整场景分开验收：子会话不可读、原生字段缺失、提供方未报告用量。不得以 session ready 等同于完整账单。
6. 同一 child 的 native 页面与群成员统计对照；旧串行多 child、完整日志与窗口 fallback 分开测试。
7. 切模型、上下文压缩、重启恢复与重复 operationId：不串指标、不重发模型、不制造精确结束时间。
8. 全组 16 位成员、100 个历史问题：默认不 retain 全部历史；连续 20 次展开/切群/关闭后引用与监听器回到基线。测试并发请求数不受查看统计影响。
9. 中英、亮暗、1440/768/390；长名称、键盘、Escape、焦点恢复；新增区域桌面一行、窄屏最多两行，无横向溢出和输入遮挡。
10. 构建、类型、单位/集成回归、`scripts/pnpm check`、工具/文档检查与实际 tgz 校验；rc.2 / rc.5 Host 和浏览器统计组合分别留证。
