# Bots 整体优化：并发协作、执行过程与页面导航审批方案

状态：**用户已批准，进入实施**。批准日期：2026-11-01。先完成 U 阶段的 Bot 展示与设置返回。

方案分支：`codex/group-concurrent-discussion`，实施基线 `a2c3adf`（已同步包含社区准备 PR #7 的 main）。用户明确授权创建跟踪 Issue、Draft PR 和按方案开发，包含必要的提交与推送；正式安装、合并和发布仍不在本轮范围。

## 1. 要达到的体验

用户提出的目标是：成员可以并发讨论；没有需要继续的工作时自然停止；长任务允许成员多轮交流、推进和交付，不要求用户逐轮点名。

本期把这个目标落实为：

- 自然群聊中，被选中的成员可同时工作，各自显示执行状态和过程。
- 成员可以提出问题、请求核验、交接工作、回应其他成员；协作消息能唤起需要继续工作的同伴。
- 成员可以明确不参与或暂时结束。没有运行、排队或在途工作时，讨论进入空闲；下一条相关请求可以继续。
- 长任务保持同一个任务关联和共享记录，多轮工作不受原来整轮 5 分钟硬截止影响。
- 单个成员停止、失败或超时，不会无条件终止其他独立成员。用户仍可停止整个任务。
- 进入 Bots 能直接找到每个 Bot，群聊和最近对话有明确入口；进入设置后，可以返回刚才的页面并保留现场。

“讨论空闲”和“任务已完成”分开：全部 Agent 不再运行只能证明当前没有待处理工作；成员宣称完成显示为“已提交结果”，由用户核验成果，不自动标记业务验收通过。

## 4. 讨论如何运行

### 4.1 模式和并发

| 场景 | 建议行为 |
| --- | --- |
| 自然群聊，没有点名 | 所有启用成员获得同一条问题及发起时的共享上下文，按并发额度开始；无须贡献的成员可 skip |
| 自然群聊，点名一个或多个成员 | 只启动点名成员；多个目标可并发 |
| 定向模式 | 保持必须选目标的规则，多个目标并发 |
| 接力/轮流模式 | 保留明确的串行规则，后者可依赖前者结果 |

建议同群最多 4 个成员同时执行，额度跨该群的活跃任务共享；超过者公平排队，并明确显示“等待执行”。同一个任务中的同一个成员只拥有一个活动执行，后续消息进入其收件箱，不叠加启动多个同身份 worker。其他群和正式私聊继续受 DSH 原生准入管理。

并发首轮使用相同的固定上下文快照，避免“谁恰好先结束”改变另一个成员的初始输入。新消息有明确的 task/message/member 关联、作者和因果引用；已公开且准入的后续内容通过 inbox 交付，不自动混入未来用户消息或私人主会话。

### 4.2 多轮协作和信息流

复用并扩展 `group_message`，将“公开发言”“要求某人继续处理”“请求其回答后回到自己”明确区分；正文中的普通 @ 字符不作为未经校验的执行指令。

1. 用户发起任务，相关成员并发进行分析或工作。
2. 成员可发布阶段结果，或向一个/多个精确 memberId 发起具体协作请求。投递必须有可去重的消息收据。
3. 目标正在工作时，新消息合并到它的原生 inbox，在合适的 step 边界处理；目标空闲时，具体协作请求可以重新唤起它。
4. 普通阶段结果进入共享记录；正在参与的成员可在下一步获得批量更新。已空闲成员不会仅因“收到、谢谢”等普通发言被全部唤醒。
5. 需要反馈的发言必须明确为请求，例如核验某项结论、补充一个缺口、处理一个子任务。请求可以定向多个成员，使多人复核并发进行。
6. 后续执行携带新的工作和引用，收到结果后可以继续下一个子步骤、请求复核或提交成果；不规定必须跑满几轮。
7. 成员明确 skip、不再提出后续工作，且执行、排队、在途投递都清空后，讨论进入空闲。

原生 sendMessage 只允许相邻的 parent/child，不能直接将兄弟成员当作相邻 Agent。跨成员投递由拥有这些子会话的群 root 桥接，分别保留原生发送身份与业务消息的实际作者/来源引用；不能伪造人工 source、借此提升权限，或绕过现有 groupChild/groupResult 的共享准入。这是 A 阶段必须实测的组合。

这选择了“有具体工作才唤醒”的默认语义。不会把每条完成通知无条件广播成全员新任务；模型也不需要不断调用工具回答“我没有工作”。成员能够在长任务中主动建立后续请求链，无需用户每一轮重新 @。

### 4.3 自然结束、等待和用户补充

结束判定由 Host 根据真实收据统一检查：没有运行的成员、没有待派发的协作请求、没有未确认投递，也没有等待处理的 inbox。检查和新请求入队在同一受控队列中完成，避免最后一个结果与新请求竞态导致丢活。

- 等待同伴：相关请求仍未完成，显示“等待同伴”；同伴失败则显示依赖未满足，不无限等待。
- 等待用户/审批：显示“等待你处理”，保留任务关联，不伪装成已完成或长时间静默。
- 空闲：没有待处理工作，保留全部历史；后续消息可继续该任务。
- 用户补充：明确“补充当前任务”或“新任务”。前者送给指定成员/当前参与者，后者分配新任务关联；单独 @ 仍可创建独立请求。
- 主动停止：提供停止该成员、停止该任务；停止该成员也暂停向该成员尚未执行的请求，避免紧接着又被自动唤醒。其他成员收到依赖停止状态。

“没有待处理工作”不等于“用户交付目标已验收”。最终交付、遇到的阻碍和待用户确认事项由参与成员明确表达。

## 5. 长任务、超时与循环控制

取消自然/定向并发讨论的默认整轮 5 分钟硬截止。排队不占成员执行时限，正常思考、检索和工具执行也不因累计过了 5 分钟而被统一取消。原生网络/模型超时和工具自身约束仍然生效。

建议的可配置默认值（均进入导出的 Config 和 schema）：

| 参数意图 | 默认建议 | 达到限制时的行为 |
| --- | --- | --- |
| 同群同时工作的成员数 | 4 | 其余公平排队，界面可见 |
| 自然讨论总时限 | 0，表示不额外设固定时限 | 用户显式配置非零值时才按此停止，并标记任务超时 |
| 单次成员执行时限 | 0，表示沿用原生执行约束 | 配置非零值时从该成员实际开始计时，超时只结束本次执行 |
| 自动后续执行额度 | 每次用户发起/明确继续后 32 次；首轮成员不计入 | 暂停新增自动唤醒，已运行成员允许收尾，显示已消耗次数和“继续讨论”；不标记成功、不丢结果 |

原 `groupRoundTimeoutMs` 保留用于明确的旧串行兼容模式；新并发模式不隐式继承它的 300000ms 默认值。新增字段的准确名称在实现契约中固定，旧记录保持可读。

自动额度是可见的循环控制，不是正常停止条件。每个 Bot 的普通 token 输出量不作为轮数，每条工具调用也不等于一次后续执行。一次明确请求可以包含多项待办。用户点“继续”才能补充额度；成员消息不能自行重置预算。

使用消息 ID/收件成员/任务代次去重，并限制自身递归唤醒；语义上的重复讨论不能靠字符串去重可靠识别，仍需真实模型体验验证。技术额度用作最后的可见暂停点，不声称已经解决模型的收敛质量。

## 6. 页面交互与成员过程

### 6.1 Bots、群聊和设置的入口

采用稳定的一级入口：**我的 Bots / 群聊 / 最近对话**，右上保留单独的“插件设置”。首次打开插件默认进入“我的 Bots”；同一客户端生命周期内再次进入，恢复上次明确选择的一级页。设置不作为再次进入的默认落点。点击 Bot/群的显式详情入口可进入对应二级页，历史 selectedId 本身不能发起导航。

| 页面 | 展示内容 | 主要操作 |
| --- | --- | --- |
| 我的 Bots | 已注册 Bot 的头像、名称、用途、可用状态；无对话、被隐藏最近对话的 Bot 仍可找到 | 开始聊天、查看资料、编辑；独立的“新建 Bot”入口 |
| 群聊 | 群名称、成员头像和名称、成员数、最近活动及运行状态 | 打开群聊、查看群资料；独立的“新建群聊”入口 |
| 最近对话 | 延续现有 Bot/群混合列表、搜索、置顶、隐藏/恢复 | 继续会话；隐藏仅影响这个列表，不等于删除 Bot 或移除群成员 |
| 群资料 | 明确标题“群聊 / 群名称”，每个成员的头像、名称与启用/不可用状态 | 打开群聊、查看成员资料、编辑成员；归档放入次要菜单 |
| 插件设置 | 标题与面包屑明确为设置；连接器、通知、定时任务、协作、IM 等现有能力 | 清晰的“返回……”按钮；涉及单个 Bot 的面板明确显示配置对象 |

“我的 Bots”的列表源仍为现有 Bot catalog，不从最近会话或群成员反推 Bot 全集。群成员的身份、是否启用与本任务的执行状态分别呈现，避免把“未参与本轮”误写成 Bot 不可用。点击成员查看资料保持返回群的路径；不会顺便发消息或新建会话。

群列表中把“群名”“成员数”“最近发言者”分行并加语义标签，避免当前 `群名 最近发言者 · 数字` 混成一句。主操作使用正常宽度按钮，不再让“打开群聊 / 编辑 / 归档”纵向占满详情区。全部沿用现有 DSH token、BotAvatar、GroupAvatar、公开 primitives 与插件布局，无需更换视觉体系。

空状态分别说明“还没有 Bot”“搜索无结果”“对话已隐藏”“加载失败”，并给出对应操作；不能统一显示成 Bot 消失。一级入口可键盘操作，选中态不只依赖颜色，头像和图标操作有可读名称。

### 6.2 设置原路返回与状态保留

进入设置时记录明确的来源视图。示例：`群聊 → deep-search 群资料 → 插件设置 → 返回 deep-search 群资料`；从我的 Bots 或最近对话进入，则分别返回其原来位置，不能统一跳到最近对话。

- 来源状态包括一级页、Bot/群的 ID 与创建代次、详情层级、搜索/筛选、滚动位置和可恢复的焦点；运行中的群会话及已存在的草稿仍由现有会话/草稿机制持有。
- 返回按钮名称对应目的地；“最近对话”只用于前往最近对话，不能再作为含糊的退出设置按钮。嵌套详情逐层返回，弹窗 Escape 只关闭当前层，并将焦点还给发起入口。
- 将“选中了哪个对象”和“用户要求打开哪个页面”分开；导航请求只消费一次。目录刷新、后台轮询及旧选中项不能抢走当前页面、重新打开设置或覆盖新选择。
- 设置中的未保存表单在离开时沿用现有确认弹窗，允许继续编辑或放弃；未保存内容不暗中提交、不跨 Bot 搬移，也不为了恢复页面而写入浏览器持久存储。只读查看可直接返回。
- 返回目标被删除/归档或创建代次已变化时，回到其所属列表并说明原因，不能打开同 ID 的另一个对象或显示空白页。页面离开不等于停止后台任务。
- 与宿主切页保持原生公开 layout/session API 的取消语义。浏览器前进/后退能否接入须另核实公开契约，本期不劫持宿主 URL/history 来伪造路由；明确的插件内返回必须可用。

本期先保证客户端内的返回现场和草稿稳定，不承诺进程退出后恢复未提交设置。插件卸载时释放视图状态和订阅，不将导航偏好变成新的业务数据存储。

### 6.3 成员执行过程

每个成员的执行卡包含：头像/名称、排队或执行状态、开始时间/耗时、当前模型、停止按钮、可展开的原生执行过程、打开完整子会话的入口。

- 实时展示原生事件中实际存在的思考块、工具调用、审批、正文流式输出；模型未提供的内容不补造。
- 对话正文和成员过程区分呈现；折叠过程后，群消息仍按实际发布顺序排列，并保留回复引用。
- 没有最终正文的成员也有状态卡，能看到其执行过什么、为何停止。
- 超时、用户停止、成员被移除、等待审批、模型/工具失败、未知恢复状态分别给出中英文说明。
- 已生成的内容保留在来源会话中；是否公开到群里继续遵守既有共享与取消边界，不把未获准的私有过程自动广播给其他模型。
- 展示与收起不会触发模型执行；重连/切换页面不能重复消息或重置滚动、草稿、展开状态。

使用公开 `conversation.content` 与 Session binding 实现内嵌过程，保留既有群 renderer 的发言者和回复能力。先验证如何约束嵌入 composer/停止动作，避免形成绕过群调度的第二个发送入口。若锁定版本无法完成所需公开嵌入，不以一个跳转链接冒充内嵌完成，应提交明确的方案修订再审批。

## 7. 实现与兼容性约束

- 继续使用原生持久子会话、现有群 tables 与消息收据；增加可选元数据和严格校验，不清空历史群、Bot 或记忆。
- 优先每任务每成员复用原生子会话。运行 spike 必须核实：后续请求的结果边界、空闲唤醒、原生审批、正确 attribution、独立停止与生命周期清理。
- 如果公开接口不能满足复用契约，先记录限制和替代方案；不私自依赖内部 Symbol、缓存或 Loader 状态，也不把一次性 spawn 包装成已经验证的长期会话。
- 群根仍不进行模型推理；不引入一个额外收费的必选“群主模型”。
- 故障恢复保留已有结果；执行结果未知的外部副作用不自动重放。重启后可以查看历史，继续执行需要明确恢复入口与去重检查。
- 所有注册、Session retain、订阅、计时器和 activation 纳入所属 `ctx.effect` 生命周期。
- 第三方依赖和 DSH 版本不随该改造顺带升级；只按真实 runtime import 增加必要 peer。
- 开发验证使用 `.dsh-dev` 隔离环境和合成模型；正式 rc.5 桌面安装与真实模型调用留到用户明确安排的验收环节。
- 新候选使用独立版本和 hash，保留已验收的 0.6.3 候选原件。

重点场景清单：

1. 三成员同时起跑，至少两者有实际重叠执行证据，不能用三个 accepted 收据代替并发。
2. 超过并发额度时公平排队；成员开始前不耗其执行时限。
3. A/B 并发完成独立分析，A 请求 B 核验，B 回答后 A 继续，再由其他成员参与；长任务不需要用户逐轮驱动。
4. 全部 skip 或没有后续请求时停止；停止后观察一段时间没有额外模型请求或定时自唤醒。
5. 普通完成通知、互相致谢、重复投递不形成无边界唤醒；额度到达后明确暂停，用户可以继续。
6. 运行中收到新请求、最后一个成员结束时恰好有新消息、同成员连续收信均不丢活、不重复启动。
7. 等待审批/用户/同伴的任务不会被误判完成；依赖失败时有可操作状态。
8. 单成员停止不影响其他独立成员；停止整个任务时排队项和活动项都收敛，迟到结果不重新启动任务。
9. 超过旧的五分钟边界仍有工作时继续执行。定时器使用受控时间验证，并补一轮超过五分钟的低请求量合成 Host 实跑。
10. 思考、工具、正文、审批和错误来自正确子会话；只读查看不泄漏其他 Bot 私聊，不再次调用模型。
11. 关闭/重开过程面板和切换群时订阅释放；取消、卸载、重启后资源与原有记录保留正确。
12. 冷启动不重发已完成结果，不重放状态未知的外部动作；老群、老消息和原候选不被覆盖。
13. `scripts/pnpm check`、工具/文档/格式检查、实际 tgz 审计以及 PR 的 Linux/macOS CI；真实模型协作质量另由用户验收。
