## 范围与顺序

1. U2：Bot 详情改为页内页面，固定身份与返回；概览、任务/消息、记忆、设置、历史直接可达。复用既有 Remote、会话打开与记忆组件。列表明确资料入口，快速创建保留，共享侧栏身份行。
2. U3：问题级过程默认紧凑，成员操作收进原生菜单；群资料窄屏返回；保留用户右/Bot 左、原生只读过程与模型/权限继承。无法公开包装派发 prompt 时保留官方详情，不改日志。
3. U4：通知记录/策略、IM/协作降级、图谱、导入导出与删除/遗忘信息层级；迁移匹配的原生控件、清理废样式；全页面回归。

按阶段创建可审查提交和 Draft PR，后续 PR 在前一阶段上叠加，合入仍由用户处理。
不升级依赖、不改群调度算法、不解除能力门控、不修改正式桌面配置或发起真实模型任务。

## 设计与原生复用

沿用已批准的 Taste 审查方向，保留宿主字体、主题与外壳。Bot 身份和每个问题下的成员过程是产品主线；列表回答“找哪个 Bot”，详情回答“这个 Bot 负责什么、有哪些工作”。
Modal、Menu、Input、Checkbox、SegmentedTabs 沿用 U0 的 rc.2/rc.5 实测；新用公共 API 要先核实声明并补实际 Host 验证。业务身份 `id+createdAt`、版本、异步响应栅栏、未保存确认继续保留。

## 验收

- 列表/群/聊天入口进入详情和返回；搜索、滚动、焦点和身份保持；保存失败保留草稿，迟到结果不污染新 Bot。
- 任务空态有可执行入口；查看/补充/停止复用原生后端，未读与完成状态准确。
- 群逐问题收折不触发模型；成员停止与整轮停止不串线，@ 与模型/权限继承回归。
- 中英、亮暗、1440/768/390；长名称、同名与 50 Bot 列表；键盘/菜单/Escape/返回可用。
- 完整 `scripts/pnpm check`、rc.2/rc.5 隔离 Host、真实 tgz 校验和 GitHub CI；每项分开记录 PASS/FAIL，不把静态检查当运行验收。
